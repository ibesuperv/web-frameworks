# Node.js: The Event Loop

The **Event Loop** is the core heart of Node.js. It is what allows Node.js to perform non-blocking, asynchronous I/O operations despite JavaScript being single-threaded. This note explains how the Event Loop works, its phases, and how code executes chronologically.

---

## 1. What is the Event Loop?

JavaScript runs on a single thread. This means it can only do one thing at a time. If we run a time-consuming operation (like downloading a large file), the thread would freeze until completed.

The Event Loop is a mechanism that allows Node.js to offload I/O tasks to the system's kernel or worker threads. When these tasks finish, the Event Loop registers their callbacks to be executed on the main thread when it becomes free.

---

## 2. Phases of the Event Loop

The Event Loop executes in a continuous loop, cycling through several distinct phases. Each phase maintains a queue of callbacks to execute.

```
       +-----------------------+
       |        START          |
       +-----------+-----------+
                   |
                   v
       +-----------+-----------+
-----> |        1. Timers      | ---> Executes callbacks from setTimeout() and setInterval()
|      +-----------+-----------+
|                  |
|                  v
|      +-----------+-----------+
|      |    2. Pending I/O     | ---> Executes deferred system callbacks (e.g., TCP errors)
|      +-----------+-----------+
|                  |
|                  v
|      +-----------+-----------+
|      |     3. Poll Phase     | ---> Retrieves new I/O events; executes I/O related callbacks
|      +-----------+-----------+
|                  |
|                  v
|      +-----------+-----------+
|      |       4. Check        | ---> Executes callbacks from setImmediate()
|      +-----------+-----------+
|                  |
|                  v
|      +-----------+-----------+
|      |    5. Close Callbacks | ---> Executes callbacks for 'close' events (e.g., socket.destroy())
|      +-----------+-----------+
|                  |
+------------------+
```

### Explanation of Key Phases:

1.  **Timers:** The event loop checks if any timers scheduled via `setTimeout()` or `setInterval()` have expired. If so, their callback functions are executed.
2.  **Pending Callbacks:** Executes I/O callbacks deferred from the previous loop iteration (such as network socket errors).
3.  **Poll:** 
    *   Node.js looks for new I/O events (file system read/write, incoming network requests).
    *   If there are I/O callbacks in the queue, it executes them.
    *   If the queue is empty, the Event Loop will temporarily wait (block) here unless there are `setImmediate()` timers waiting.
4.  **Check:** Executes callbacks scheduled by `setImmediate()`.
5.  **Close Callbacks:** Executes cleanup callbacks like `socket.on('close', ...)` or stream destructions.

---

## 3. Microtask Queue (Important Exam Concept)

Aside from the Event Loop phases, there is a **Microtask Queue** which contains callbacks for:
1.  `process.nextTick()`
2.  `Promise` resolution (`.then()`, `.catch()`, `async/await`)

**Rule:** The Microtask Queue is checked **between every phase** of the Event Loop. If there are any callbacks in the Microtask Queue, they are executed *immediately* before the event loop advances to the next phase. `process.nextTick()` has higher priority than Promise callbacks.

---

## 4. Let's Trace: Asynchronous Code Execution

To understand the Event Loop, let's trace the execution of the following program:

```javascript
const fs = require('fs');

console.log("1. Start of Program");

setTimeout(() => {
    console.log("2. setTimeout (Timer Phase)");
}, 0);

setImmediate(() => {
    console.log("3. setImmediate (Check Phase)");
});

process.nextTick(() => {
    console.log("4. nextTick (Microtask)");
});

console.log("5. End of Program");
```

### Execution Trace:
1.  **Main Thread Execution (Synchronous Code):**
    *   Prints `"1. Start of Program"`.
    *   Schedules `setTimeout` (registered in Timers queue).
    *   Schedules `setImmediate` (registered in Check queue).
    *   Schedules `process.nextTick` (registered in Microtask queue).
    *   Prints `"5. End of Program"`.
2.  **Microtask Execution:**
    *   Main script ends. Before entering the Event Loop, Node checks the Microtask Queue.
    *   Executes `process.nextTick` callback -> Prints `"4. nextTick (Microtask)"`.
3.  **Event Loop Starts:**
    *   **Phase 1: Timers:** Finds the expired `setTimeout` callback -> Prints `"2. setTimeout (Timer Phase)"`.
    *   **Phase 2 & 3: Pending & Poll:** Queues are empty. Moves to Check phase.
    *   **Phase 4: Check:** Finds the `setImmediate` callback -> Prints `"3. setImmediate (Check Phase)"`.

### Output:
```text
1. Start of Program
5. End of Program
4. nextTick (Microtask)
2. setTimeout (Timer Phase)
3. setImmediate (Check Phase)
```
