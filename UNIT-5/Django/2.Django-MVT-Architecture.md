# Django: MVT Architecture

One of the most common questions on Django exams is how it structures code. Django uses the **MVT (Model-View-Template)** architecture, which is a software design pattern similar to MVC.

---

## 1. What is MVT?

MVT stands for **Model-View-Template**. 

*   **M - Model:** Manages the data and database rules. It is a Python class that maps to a single database table.
*   **V - View:** Contains the business logic. It receives HTTP requests, interacts with the Model to fetch data, and decides which Template (HTML) to render.
*   **T - Template:** The presentation layer. It is an HTML file mixed with **Django Template Language (DTL)** tags to dynamically render data passed from the View.

---

## 2. The MVT Request-Response Flow

Unlike classical setups where a Controller handles client requests, Django’s internal controller (the routing engine) automatically forwards URLs to the correct View.

```
                  +----------------------+
                  |    Client Browser    |
                  +----------+-----------+
                             |  1. Request URL
                             v
                  +----------+-----------+
                  |      URL Router      | (urls.py matches pattern)
                  +----------+-----------+
                             |  2. Calls View
                             v
                  +----------+-----------+
    +------------>|      View (views.py) |<------------+
    |             +----------+-----------+             |
    |                        |                         |
    | 3. Query Data          | 5. Send Data            | 6. Render
    v                        v                         v
+---+---+                +---+---+                 +---+---+
| Model | (models.py)    | Context |               |Templ. | (HTML + DTL)
+-------+                +-------+                 +-------+
```

### Flow Steps:
1.  **Request:** A user enters a URL in their browser.
2.  **URL Routing (`urls.py`):** Django searches the URL configurations. Once it matches, it calls the corresponding **View** function or class.
3.  **Data Retrieval (`models.py`):** If database operations are required, the **View** communicates with the **Model**.
4.  **Database Action:** The model translates the python query to SQL and retrieves data from the database.
5.  **Context Assembly:** The View wraps the retrieved data into a dictionary called a **Context**.
6.  **Template Rendering:** The View passes the context to the **Template**. Django replaces template tags (like `{{ username }}`) with actual values and returns a raw HTML document back to the browser.

---

## 3. Difference Between MVC and MVT

Although MVT is closely related to the traditional Model-View-Controller (MVC) pattern, the naming and responsibilities differ slightly:

| Feature | MVC (Model-View-Controller) | MVT (Model-View-Template) |
| :--- | :--- | :--- |
| **Data Layer** | **Model**: Handles database structures. | **Model**: Handles database structures. |
| **Logic Layer** | **Controller**: Handles user input and directs program flow. | **View**: Contains business logic and interacts with Models/Templates. |
| **UI Layer** | **View**: Displays data to the user. | **Template**: Defines how data is presented (HTML). |
| **Controller Task** | Developer has to write routing and controller logic explicitly. | **Django Framework** itself handles the controller task (URL routing). |
